# Weather Station API

FastAPI + SQLite backend for local development. Requires Python 3.11 or newer.

## Setup

Use **PowerShell on Windows** or **Bash on Linux**. In VS Code on Windows, select **Terminal: Select Default Profile > PowerShell**, then open a new terminal.

Run commands from the repository root. Create the virtual environment once and install dependencies inside it, not globally. Only commands that differ between platforms are shown separately.

**Windows / PowerShell** (adjust the project path if needed):

```powershell
cd C:/Projects/esp32-weather-station
python -m venv backend/.venv
./backend/.venv/Scripts/python.exe -m pip install -r backend/requirements-dev.txt
```

If `python` is not recognized, try `py -3.11 -m venv backend/.venv` with Python 3.11 installed.

**Linux / Bash** (adjust the project path if needed):

```bash
cd ~/Projects/esp32-weather-station
python3 --version
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements-dev.txt
```

Use Python 3.11 or newer. If your default `python3` is older, select a compatible installed interpreter, for example `python3.11 -m venv backend/.venv`.

On Debian/Ubuntu, if creating the environment fails because `venv` or `ensurepip` is missing, install the matching OS package (for example `sudo apt install python3-venv` for the default Python), then retry. Other distributions use different package managers. Do not use `sudo pip` or install project dependencies into the system Python.

For runtime dependencies only, use `backend/requirements.txt` instead. Activation is not required on either platform: all commands explicitly use the virtual environment's interpreter. No PowerShell execution policy changes are needed because there is no activation script to run.

If the interpreter path is not found, check that you are in the repository root and have created `backend/.venv`. Create a separate virtual environment on each machine/OS; do not copy the Windows `.venv` to Linux.

## Run

From the repository root:

**Windows / PowerShell:**

```powershell
./backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

**Linux / Bash:**

```bash
backend/.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

Open <http://127.0.0.1:8000/docs> to try the API interactively.

**Windows CMD** (alternative, from the repository root after creating the virtual environment and installing dependencies):

```bat
backend\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

Keep the terminal open while using the API. Press **Ctrl+C** to stop the server. To start it again, run the same command; you do not need to recreate the virtual environment.

To allow an ESP32 on the same trusted local network to connect, replace `--host 127.0.0.1` with `--host 0.0.0.0`. Use your computer's LAN IPv4 address (find it with `ipconfig` on Windows or `ip -4 addr` on Linux) in the ESP32 configuration, not `localhost`, `127.0.0.1`, or `0.0.0.0`. Select the Wi-Fi/Ethernet interface connected to the ESP32's network, not a loopback, VPN, or container interface. Your firewall may require an inbound allowance for TCP port 8000 from your trusted local network; do not disable the firewall.

This version has **no authentication or TLS**. Do not expose it to the Internet or forward the port on your router. The computer must remain running to receive readings.

## Endpoints

| Method | Path | Description |
| --- | --- | --- |
| GET | `/health` | Check the API and database connection |
| POST | `/api/readings` | Validate and store a reading (201) |
| GET | `/api/readings/latest` | Last received reading; optional `device_id` filter (404 if empty) |
| GET | `/api/readings` | History, newest received first; optional `device_id`, `limit` (1–1000), and `offset` |

Example request body:

```json
{
  "device_id": "esp32-01",
  "temperature_c": 24.3,
  "humidity_pct": 58.2,
  "measured_at": "2026-10-24T15:00:00Z"
}
```

- `measured_at` is optional and may be null. It represents the device's measurement time and requires a timezone (`Z` or an explicit UTC offset). The server normalizes it to UTC.
- `received_at` is always generated by the server in UTC and cannot be supplied by the client. Keep the server's clock synchronized.
- Until the ESP32 has a synchronized clock, omit `measured_at` rather than inventing a measurement time. Reception time is not necessarily measurement time.
- Responses include both timestamps and an integer `id`. History and latest results are ordered by insertion ID, not device time.
- Temperature is limited to the DHT22 range (-40 to 80 °C); humidity must be between 0 and 100%. Non-finite values and unknown fields are rejected with 422.

Examples without a device timestamp, run in a second terminal while the server is running:

**Windows / PowerShell:**

```powershell
$body = @{ device_id = "esp32-01"; temperature_c = 24.3; humidity_pct = 58.2 } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/readings -ContentType "application/json" -Body $body
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/readings/latest
```

**Linux / Bash**, in a second terminal while the server is running (requires `curl`):

```bash
curl -X POST http://127.0.0.1:8000/api/readings \
  -H 'Content-Type: application/json' \
  -d '{"device_id":"esp32-01","temperature_c":24.3,"humidity_pct":58.2}'
curl http://127.0.0.1:8000/api/readings/latest
```

The current firmware does not send HTTP readings yet; use `/docs` or the examples above to test the backend first.

## Storage

SQLite uses `backend/data/weather.sqlite3` by default, independent of the terminal's working directory. This directory and `backend/.venv` are excluded from Git. Data persists across server restarts.

Override the database path before starting the server if needed:

**Windows / PowerShell:**

```powershell
$env:WEATHER_DATABASE_PATH = "C:/path/to/weather.sqlite3"
```

This setting applies to the current PowerShell session and its child processes. To return to the default path, run `Remove-Item Env:WEATHER_DATABASE_PATH` before restarting the server.

**Linux / Bash:**

```bash
export WEATHER_DATABASE_PATH="$HOME/weather-data/weather.sqlite3"
```

This setting applies to the current shell and its child processes. To return to the default path, run `unset WEATHER_DATABASE_PATH` before restarting the server.

## Project structure

```text
app/
  main.py       Application factory, database path configuration, and startup
  schemas.py    Pydantic request and response validation
  database.py   SQLite connections, initialization, and queries (no HTTP logic)
  routes.py     HTTP endpoints registered through an APIRouter
tests/
  test_api.py   API validation, persistence, and database isolation tests
```

`create_app(database_path=...)` allows each application instance to use its own SQLite file. Connections are opened and closed per database operation; no connection is shared globally.

## Tests

From the repository root:

**Windows / PowerShell:**

```powershell
./backend/.venv/Scripts/python.exe -m pytest backend/tests
```

**Linux / Bash:**

```bash
backend/.venv/bin/python -m pytest backend/tests
```

Tests use isolated temporary SQLite databases and never modify your development readings.
